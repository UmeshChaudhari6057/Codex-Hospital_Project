🏥 Hospital Management Microservices

Complete Technical Documentation & Architecture Guide

Built with Java 21, Spring Boot 3.2.5, and Modern Microservices Patterns

📋 Project Overview

The Hospital Management Microservices project is a comprehensive, production-ready implementation of a microservices architecture designed specifically for healthcare management. This system demonstrates modern Java enterprise application development using cutting-edge technologies and best practices.

🎯 Project Objectives

Scalability

Each microservice can be scaled independently based on demand, ensuring optimal resource utilization and performance.

Maintainability

Separate business domains into distinct services with clear boundaries, making the codebase easier to maintain and evolve.

Resilience

Implement circuit breakers, retries, and fallback mechanisms to ensure system reliability even when individual services fail.

Flexibility

Technology-agnostic communication between services allows for independent technology choices and upgrades.

🏗️ System Architecture

Microservices Architecture Pattern

This project implements a true microservices architecture with the following key characteristics:

  • Service Autonomy - Each service is independently deployable and scalable
  • Database per Service - Each microservice has its own database instance
  • Service Discovery - Dynamic service registration and discovery via Eureka
  • API Gateway - Single entry point with routing and load balancing
  • Inter-Service Communication - Both synchronous (Feign) and asynchronous (Kafka)
  • Resilience Patterns - Circuit breakers, retries, and fallbacks

🔄 Communication Patterns

Synchronous Communication

Technology: OpenFeign

Use Case: When immediate response is required

Example: Appointment service calls Patient service to validate patient data

Benefits: Simple to implement, immediate consistency

Asynchronous Communication

Technology: Apache Kafka

Use Case: Event-driven updates and notifications

Example: Appointment created event triggers notification service

Benefits: Decoupled services, improved reliability, event sourcing

🎨 Architecture Patterns Implemented

Database per Service Pattern

Each microservice has its own database instance for data isolation and independent scaling. This ensures that services are loosely coupled and can evolve their data schemas independently.

Databases: user_db, patient_db, doctor_db, appointment_db

Service Discovery Pattern

Services register themselves with Eureka server on startup and discover other services dynamically. This eliminates hardcoded service URLs and enables dynamic scaling.

Implementation: Eureka Server + Eureka Clients

API Gateway Pattern

Single entry point for all client requests, handling routing, load balancing, and cross-cutting concerns like authentication and rate limiting.

Implementation: Spring Cloud Gateway

Circuit Breaker Pattern

Prevents cascading failures by stopping calls to failing services and providing fallback responses. Improves system resilience and user experience.

Implementation: Resilience4j with custom fallbacks

Event-Driven Architecture

Services communicate asynchronously through events published to Kafka topics. This decouples services and enables eventual consistency.

Implementation: Spring Kafka with Appointment events

Saga Pattern

Distributed transaction management where each service performs local transactions and publishes events to trigger next steps in the saga.

Implementation: Kafka events for appointment lifecycle

🔐 Authentication Flow

Registration

1. Client sends user data to /auth/register

2. Service validates input and checks for duplicates

3. Password is encrypted using BCrypt

4. User is saved to database

5. UserDto is returned to client

Login

1. Client sends credentials to /auth/login

2. Service validates username and password

3. JWT token is generated with user claims

4. Token and role are returned to client

5. Client stores token for future requests

⚙️ Key Features

  • JWT Authentication: Stateless token-based authentication
  • Role-Based Access: Support for PATIENT, DOCTOR, ADMIN roles
  • Password Encryption: BCrypt password encoding
  • Token Validation: JWT token validation endpoint
  • User Management: CRUD operations for user data
  • Security Configuration: Spring Security integration

common/
├── src/main/java/com/hospital/common/

🎯 Purpose

                
    
                    
  • Code Reusability: Shared DTOs avoid duplication across services
    • 
                    
  • Type Safety: Consistent data structures across microservices
    • 
                    
  • Event Definitions: Centralized event structure for Kafka
    • 
                    
  • Validation: Common validation annotations for DTOs
    • 
                    
  • Maintenance: Single source of truth for shared contracts
